## Session 14:xx (voice HUD debug investigation)

### What was done
- Investigated bug: HUD shows "Listening" but transcript and executed commands never appear
- Root cause: `session.update` was sent immediately on connect, before OpenAI server sent `session.created` — OpenAI Realtime API expects the client to respond to `session.created` before configuring the session
- Added `sessionCreated` event handling to `VoiceRealtimeTransport`
- Moved `session.update` send from `activate()` to an `onSessionCreated` callback — now sent only after the server ACKs session creation
- Added `#if DEBUG` cmuxDebugLog logging for all received WebSocket events, errors, session handshake, and transcripts — surfaces exact event types coming back from OpenAI
- Guarded empty transcript strings (decode fallback returns "" which would hide the view)
- Build verified: `** BUILD SUCCEEDED **`

### Current state
- Branch: `feat/voice-input` — changes uncommitted, test build at tag `voice-debug`
- Protocol flow is now correct: connect → wait for session.created → send session.update → audio flows
- Debug log shows every event type received (`voice.ws.recv event=...`) and errors (`voice.ws.error ...`)

### Key decisions
- Audio capture still starts immediately in `activate()` for UX (mic tap fires quickly; audio before `session.update` is processed with OpenAI defaults and likely discarded anyway)
- If voice still doesn't work after this fix, `tail -f /tmp/cmux-debug-voice-debug.log | grep voice` will show exactly what's happening on the wire

### Next steps
